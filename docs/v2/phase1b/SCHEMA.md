# Phase 1B Schema Document — Unified Signals & Metadata

This document defines the schema DDL, the Unified Signal representation, and the Financial Transaction metadata schema.

---

## 1. Updated Database Schema: `mobile_signals`

The `mobile_signals` table in `jarvis_insights_schemav1` has been updated with a `metadata jsonb` column to store source-specific signals.

```sql
create table jarvis_insights_schemav1.mobile_signals
(
    id bigint generated by default as identity primary key,
    device_id text not null,
    source text not null,
    sender text not null,
    message text not null,
    mobile_timestamp timestamptz not null,
    processed boolean default false,
    created_at timestamptz default now(),
    message_hash text unique,
    metadata jsonb
);
```

---

## 2. Unified Signal Schema

All collectors emit the unified signal structure shown below:

```json
{
  "signal_id": "uuid",
  "source_type": "whatsapp | sms | financial",
  "source_subtype": "chat | inbox | gpay | bank_statement",
  "source_file_name": "filename.json",
  "source_file_hash": "sha256_hex",
  "source_event_time": "ISO-8601 UTC timestamp",
  "source_ingested_at": "ISO-8601 UTC timestamp",
  "sender": "sender name or number",
  "receiver": "receiver name or number",
  "content": "raw message text or transaction description",
  "metadata": {}
}
```

### Database Mapping Table

| Unified Signal Field | `mobile_signals` Column | Notes |
|---|---|---|
| `signal_id` | `metadata ->> 'signal_id'` | Generated unique UUID. |
| `source_type` | `source` | Broad signal category. |
| `source_subtype`| `metadata ->> 'source_subtype'`| Granular collector type. |
| `source_file_name`| `metadata ->> 'source_file_name'`| Name of processed file. |
| `source_file_hash`| `metadata ->> 'source_file_hash'`| SHA-256 hash of processed file. |
| `source_event_time`| `mobile_timestamp` | **Preserved event timestamp** (historical). |
| `source_ingested_at`| `metadata ->> 'source_ingested_at'`| Actual ingestion time. |
| `sender` | `sender` | Source message sender. |
| `receiver` | `device_id` | Default receiver context. |
| `content` | `message` | Raw message body or description. |
| `metadata` | `metadata` | Full JSONB metadata block. |

## 3. Financial Transaction Schema

For GPay statements and bank statements, a standardized transaction dictionary is stored under `metadata`:

```json
{
  "transaction_date": "ISO-8601 UTC timestamp",
  "amount": 17900.0,
  "currency": "INR",
  "transaction_type": "DEBIT | CREDIT",
  "description": "narration or details",
  "reference_number": "reference number",
  "counterparty": "name or merchant"
}
```
