## 3. Approved Connection Method

All connections to Supabase must utilize the `supabase-py` client library and connect via REST/Table APIs using the Service Role Key.

```python
from supabase import create_client, Client, ClientOptions

options = ClientOptions(schema="jarvis_insights_schemav1")
client: Client = create_client(supabase_url, supabase_key, options=options)
```

## 6. Manual Prerequisites

The database table `jarvis_insights_schemav1.v1_connectivity_test` must exist before the validation script can run. The table should NOT be created automatically or dynamically via application code.

If the table needs to be created or recreated, run the following SQL statement manually in the Supabase SQL Editor:

```sql
CREATE TABLE jarvis_insights_schemav1.v1_connectivity_test (
    id bigint generated by default as identity primary key,
    created_at timestamptz default now(),
    test_message text,
    file_count integer,
    execution_time timestamptz
);
```

## 9. Key Connection Findings (Reference)

* **Direct Host IPv6-Only Limitation:**  
  The direct PostgreSQL connection host (`db.tbwnyuampjoamgarwwoo.supabase.co`) does not have IPv4 DNS records (it is IPv6-only). Because default WSL environments lack IPv6 routing, direct connection attempts fail with `Network is unreachable`.
* **Connection Pooler Timeout (Port 443):**  
  Attempts to connect via port 443 fail with `timeout expired` due to firewalls dropping PostgreSQL protocol packets over port 443.
* **REST API Bypass:**  
  The Supabase REST API (HTTPS over port 443) bypasses these PostgreSQL protocol and routing issues entirely, providing a stable and performant pipeline.
