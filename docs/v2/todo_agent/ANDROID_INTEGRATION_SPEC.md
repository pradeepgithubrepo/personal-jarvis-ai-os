# ANDROID INTEGRATION SPECIFICATION
**Jarvis V1 Personal Operating System — To-Do App Integration Specs**

---

## 1. Architectural Overview & Synchronization Model

To support private, offline-friendly operation:
* **The Laptop Backend**: Offline most of the time, waking up only **3 times a day** to parse ingestion queues.
* **The Cloud Supabase DB**: Always online. Acts as the real-time sync database.
* **The Android App**: Always online. Reads and writes directly to Supabase.

```
+-------------+              +-------------+              +-------------+
| Android App | <== Sync ==> | Supabase DB | <== Sync ==> |   Laptop    |
| (Always On) |              | (Always On) |              | (Wakes 3x)  |
+-------------+              +-------------+              +-------------+
```

Because of this offline-laptop topology, the **Android App is responsible for scheduling all reminders and alerts locally on the device** based on the database state. The laptop backend does not push notifications.

---

## 2. Supabase Task Schema

The Android app will sync tasks from the `jarvis_insights_schemav1.tasks` table.

### Schema Fields
* **`id`** (UUID): Unique primary key.
* **`title`** (TEXT): Short, human-oriented imperative summary (e.g. *"Pay TNEB Electricity Bill"*).
* **`description`** (TEXT): Longer task notes.
* **`status`** (ENUM): `OPEN` | `IN_PROGRESS` | `COMPLETED` | `CANCELLED` (Default: `OPEN`).
* **`priority`** (ENUM): `LOW` | `MEDIUM` | `HIGH` | `URGENT` (Default: `MEDIUM`).
* **`due_datetime`** (TIMESTAMPTZ): Task deadline.
* **`notification_profile`** (TEXT): Enforces alert schedule (`NONE` | `STANDARD` | `IMPORTANT` | `CRITICAL`).
* **`source_type`** (ENUM): `AUTO_GENERATED` | `USER_TEXT` | `USER_VOICE`.
* **`route_id`** (UUID): Nullable. References `signal_routes(id)` if auto-generated by Jarvis.
* **`created_by`** (ENUM): `JARVIS` | `USER`.
* **`assigned_to`** (TEXT): Owner string (e.g. `"Pradeep"`).
* **`created_at`** (TIMESTAMPTZ): Created timestamp.
* **`updated_at`** (TIMESTAMPTZ): Last updated timestamp.
* **`completed_at`** (TIMESTAMPTZ): Slipped/completed timestamp.

## 3. Real-Time Sync Logic

Use the Supabase Kotlin/Java client to subscribe to realtime updates on the `tasks` table.

```kotlin
// Example Kotlin Supabase subscription code
val channel = supabase.realtime.createChannel("tasks_sync") {
    schema = "jarvis_insights_schemav1"
    table = "tasks"
}

channel.postgresChangeFlow<PostgresAction>().collect { action ->
    when (action) {
        is PostgresAction.Insert -> handleTaskCreated(action.record)
        is PostgresAction.Update -> handleTaskUpdated(action.record)
        is PostgresAction.Delete -> handleTaskDeleted(action.oldRecord)
    }
}
```

## 4. Client-Side Local Notification Scheduling

The Android app must schedule local alerts using `AlarmManager` or WorkManager based on the `notification_profile` column.

### Profile Mapping Rules
Upon task sync, check the `status`. If `status` is not `OPEN`, cancel any existing alarms for this task. If `status` is `OPEN`, schedule alarms relative to `due_datetime` at **09:00 AM local time**:

| Notification Profile | Alarm Frequency | Scheduled Alarms (at 09:00 AM Local Time) |
|:---|:---|:---|
| **`NONE`** | 0 alarms | No alarms scheduled. |
| **`STANDARD`** | 1 alarm | `due_datetime - 1 day` |
| **`IMPORTANT`** | 2 alarms | `due_datetime - 1 day` AND `due_datetime` |
| **`CRITICAL`** | 3 alarms | `due_datetime - 7 days` AND `due_datetime - 1 day` AND `due_datetime` |

```kotlin
// Example Alarm Scheduling calculation
fun getAlarmTimes(due: Instant, profile: String): List<Instant> {
    val nineAMToday = LocalDateTime.of(LocalDate.now(), LocalTime.of(9, 0))
    val nineAMDue = due.atZone(ZoneId.systemDefault()).toLocalDate().atTime(9, 0)
    
    return when (profile) {
        "STANDARD" -> listOf(nineAMDue.minusDays(1))
        "IMPORTANT" -> listOf(nineAMDue.minusDays(1), nineAMDue)
        "CRITICAL" -> listOf(nineAMDue.minusDays(7), nineAMDue.minusDays(1), nineAMDue)
        else -> emptyList()
    }.map { it.atZone(ZoneId.systemDefault()).toInstant() }
     .filter { it.isAfter(Instant.now()) } // Don't schedule alerts in the past
}
```

## 5. Speech-to-Text Voice Flow

To keep the pipeline fast and offline-friendly, Speech-to-Text (STT) is processed **entirely on the Android device**:

1. **User Voice Ingestion**: The user presses "Speak Task" on the app.
2. **Audio Transcription**: The app uses Android's native `SpeechRecognizer` (or on-device library) to transcribe audio immediately.
3. **Structured NLP Extraction (Local or Lightweight)**:
   - Extract the task name and temporal keywords (e.g., *"tomorrow"* or *"next Friday"*).
4. **Supabase Write**: Create the task payload and insert directly into Supabase:
   ```json
   {
     "title": "Call Harish",
     "due_datetime": "2026-07-12T09:00:00Z",
     "notification_profile": "STANDARD",
     "source_type": "USER_VOICE",
     "created_by": "USER",
     "assigned_to": "Pradeep",
     "status": "OPEN"
   }
   ```

## 6. Source Traceability ("View Source")

For tasks auto-generated by Jarvis (`created_by = 'JARVIS'`), the app must allow the user to view the original messy text message that generated the task.

### Fetching Source Message Lineage
Retrieve the raw message using the `route_id` reference:

```javascript
// supabase query to trace lineage
const { data, error } = await supabase
  .from('tasks')
  .select(`
    route_id,
    signal_routes (
      understood_signals (
        qualified_signals (
          mobile_signals (
            message
          )
        )
      )
    )
  `)
  .eq('id', taskId)
  .single();

const originalMessage = data.signal_routes.understood_signals.qualified_signals.mobile_signals.message;
```
Display this `originalMessage` text in the task details screen under a **"Source Signal"** info card.
